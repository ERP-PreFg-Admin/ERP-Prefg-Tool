feat: optimize invoice extraction, costing approvals, and masters tables

Invoice extraction
------------------
Read the PDF's existing text layer before calling Nanonets. unpdf was already
extracting the text to identify the seller GSTIN, but the remaining invoice text
was being discarded. Local parsing now handles supported invoice layouts before
falling back to Nanonets.

lib/invoice-local/ adds local parsers for Tally, Cheryl, and Jainam layouts.
Tally parsing is column-based so additional suppliers with the same layout do
not require new code.

Local results are accepted only when qty x rate = amount for every row and the
GST/total validation passes. Invalid or uncertain parses fall through to
Nanonets. v1 remains contract-compatible with a single switch in invoice-api.ts
to restore the metered path if required.

Buyer vs seller GSTIN
---------------------
Fixed lookupMfgByGstin and strategyFor selecting the first matching GSTIN.
lib/gstin.ts now filters PEP's own registrations by PAN so the buyer GSTIN is
not incorrectly treated as the supplier GSTIN.

Invoice upload limit
--------------------
Increased the Nginx invoice upload limit to support larger PDF invoices.
Upload limits are kept in a dedicated conf.d file so certbot renewals do not
overwrite them.

The client now rejects oversized files before upload.

Misc costs
----------
Job Work, Shrink Wrap, Shipper, and RM-PM Wastage now go through the same
approval gate as RM/PM rates instead of writing directly to bom_misc.

Costing queries only use active records, preventing in_review prices from
affecting Total Costing.

Agreed Final Costing
--------------------
Standardized comparison table columns through ag-columns.tsx so labels,
widths, and cell rendering are consistent across all four tables.
